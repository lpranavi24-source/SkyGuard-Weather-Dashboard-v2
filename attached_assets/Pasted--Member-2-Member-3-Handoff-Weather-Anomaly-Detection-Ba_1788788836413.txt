## 3. Example Queries You'll Need

### Get all stations for the map
```javascript
const { data: stations } = await supabase
  .from('stations')
  .select('*')
```

### Get latest anomaly status per station (for map pin color)
```javascript
const { data } = await supabase
  .from('anomalies')
  .select('*')
  .eq('station_id', 'AWS-01')
  .order('timestamp', { ascending: false })
  .limit(1)
```

### Get full detail for one anomaly (matches your "Anomaly Details" screen spec)
```javascript
const { data: anomaly } = await supabase
  .from('anomalies')
  .select('*')
  .eq('id', anomalyId)
  .single()

const { data: reading } = await supabase
  .from('sensor_readings')
  .select('*')
  .eq('station_id', anomaly.station_id)
  .eq('timestamp', anomaly.timestamp)
  .single()

const { data: alert } = await supabase
  .from('alerts')
  .select('message')
  .eq('anomaly_id', anomalyId)
  .maybeSingle()   // null if it was a NORMAL reading — no explanation generated
```

This gives you everything for the anomaly detail card:
```
AWS-07
Temperature: 82°C
Isolation Forest: [from anomaly.reason]
Diagnosis: [anomaly.fault_type]
Recommendation: [anomaly.recommendation]
Explanation: [alert.message]
```

### Get temperature/humidity/pressure history for charts
```javascript
const { data: history } = await supabase
  .from('sensor_readings')
  .select('timestamp, temperature, humidity, pressure')
  .eq('station_id', 'AWS-01')
  .order('timestamp', { ascending: true })
```

### Mark anomalous points on the chart
Cross-reference `sensor_readings.timestamp` with `anomalies.timestamp` where `final_status != 'NORMAL'` — same station, matching timestamp.

### Dashboard summary stats
```javascript
const { data: all } = await supabase
  .from('anomalies')
  .select('final_status')
  .eq('station_id', 'AWS-01')

const normal = all.filter(a => a.final_status === 'NORMAL').length
const possible = all.filter(a => a.final_status === 'POSSIBLE ANOMALY').length
const faults = all.filter(a => a.final_status === 'SENSOR FAULT').length
```

## 5. Important Notes

- **Not all anomalies have explanations.** Only non-`NORMAL` rows have a matching `alerts` row. Handle the `null` case in your UI (e.g., don't show an explanation box for normal readings).
- **`temporal_result` / `spatial_result` / `cross_sensor_result` / `evidence_count` are sometimes NULL** — this depends on which data batch a row came from. Handle gracefully (e.g., hide that field if null) rather than assuming it's always populated.
- **STATION_B and STATION_C don't have their own anomaly records** — they're reference-only stations for AWS-01's spatial comparison. Don't expect anomaly pins for them.
- **Timestamps are stored with timezone info** (IST, `+05:30`) — make sure your date formatting handles this correctly, not just UTC.
